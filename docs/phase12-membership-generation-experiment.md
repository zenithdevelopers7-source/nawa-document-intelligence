# Synthetic membership-generation experiment

This integration draft adds database-assigned membership, identity and tenant generations and binds a process-local session to the generations returned by the server-side membership lookup. Changing a membership's active state or role, changing an identity or tenant's active state, or recreating the corresponding record assigns a new generation. On the next protected request, a mismatched generation invalidates the old session; a newly authenticated session can use the current generations.

Migrations `005_membership_generation.sql` and `006_identity_tenant_generation.sql` are new and leave previous migration files and their checksums unchanged. The tests apply them only to disposable synthetic databases, including upgrades from prior schemas. No migration of existing NAWA workspaces, uploads or databases is authorized or performed by this experiment.

This is not a production revocation guarantee. Provider-side disablement and account sessions are not synchronized. A stale database restore can reinstate old generations: a still-running process may accept an unexpired session whose intervening revocation it never observed. A disposable test characterizes this risk and explores explicit `begin_recovery`/`end_recovery` calls that clear and pause each process-local session store. These methods are not connected to a recovery service or HTTP endpoint. Calling one store does not protect another; the caller must externally quiesce and drain operations, pause every process before restoring, validate recovery, and only then resume. In-flight work already authorized outside the store is not cancelled. A database restore can also rewind sequence state, and privileged database users can alter triggers or data. Distributed invalidation, coordinated backup and recovery, and independent security review remain open. The browser test uses a disposable CI-only certificate and synthetic identities.

A separate synthetic callback-ordering experiment stops on a failed quiesce, drain, pause, restore or verification and leaves successfully paused stores paused for manual release. Its callbacks are trusted test stubs, not evidence of actual traffic draining, operator authorization or distributed coordination. Failed or partial callbacks may leave external state uncertain. The database test uses two stores in one process and a disposable restored database; it does not prove multi-process recovery.

An additional local HTTP characterization demonstrates that a request already authorized before a store pause may complete afterward, while a new request using the old session is rejected. This test documents a gap; it is not a request-draining implementation or a production safety guarantee.

A separate `SyntheticRequestGate` experiment enrolls operations in one process. The draft protected handler accepts it through an explicit opt-in used by synthetic tests; the running portal is not configured with it. The opted-in handler rejects new GET and POST requests after closure, waits for an active enrolled request to finish, then invokes a synthetic restore callback. A timed-out drain keeps that gate closed and does not invoke restore. It does not cover background workers or other processes; restore and verification callbacks in the HTTP test are stubs. Correct use requires enrollment of every relevant operation and externally controlled release, which this prototype cannot guarantee. Real multi-process draining, recovery authorization and independent review remain open.
